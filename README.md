# ExpressiveAI.online

ExpressiveAI is a Next.js + Express application with Clerk authentication, Supabase data/storage, a Redis/BullMQ generation queue, and Stripe one-time credit checkout.

## Local startup

Secrets are delivered at runtime by Infisical instead of being read from `.env` files on disk. The one-time account, project and CLI setup is in [`docs/infisical.md`](docs/infisical.md).

1. Install dependencies with `pnpm install`.
2. Install and log in to the Infisical CLI, then run `infisical init` inside `apps/web`, `apps/api` and `apps/worker` so each app links to its Infisical project. That writes a `.infisical.json` per app, which contains no secrets and is safe to commit.
3. Start the monorepo with `pnpm dev`. Each app's `dev` script runs `infisical run --env=dev -- …`, so no `.env` file is needed locally and application code still reads `process.env` unchanged.

If you have not onboarded to Infisical yet, run the unwrapped scripts instead: `pnpm --filter @expressiveai/web dev:local` (also available as `dev:local` / `start:local` in the API and worker).

## Recommended providers and account setup

The app needs provider accounts and project-specific credentials; those are issued by the services and cannot be generated by this repository.

| Capability | Recommended provider | Where to configure | Credential / setup |
| --- | --- | --- | --- |
| Account auth | Clerk | `dashboard.clerk.com` | Publishable key in the web app, secret key + JWKS URL/issuer in API, Clerk user lifecycle webhook at `/api/webhooks/clerk` |
| Database and video storage | Supabase | `supabase.com/dashboard` | Project URL + service-role key for API/worker; create the configured public video bucket and apply `packages/database/src/schema.sql` |
| Text-to-video inference | Hugging Face Inference Providers (fal-ai routing) | `huggingface.co/settings/tokens` | Fine-grained token with Inference Providers permission as `HF_TOKEN`; `HUGGINGFACE_MODEL_ID` defaults to `Wan-AI/Wan2.1-T2V-1.3B` |
| Durable generation queue | Upstash Redis or managed Redis | `console.upstash.com` | TLS Redis URL (`REDIS_URL`) for BullMQ, shared by API and worker |
| Checkout | Stripe | `dashboard.stripe.com` | Test/live secret key, publishable key, and webhook signing secret; configure webhook for `/api/payments/webhook` and `checkout.session.completed` |
| Transactional email (optional) | Resend SMTP | `resend.com` | SMTP credentials / verified sender if email features are enabled |

The public home, pricing, and gallery pages do not need external credentials. A production deploy does need the services above, reachable API/worker deployment, a persistent Redis queue, and a configured storage bucket. Never put provider secret keys in `NEXT_PUBLIC_*` variables.

### Important video-duration limitation

The worker submits an 81-frame source-scene request through Hugging Face's routed fal-ai queue, downloads the result, then uses FFmpeg to loop/re-encode it to the requested runtime. The selector/API supports up to five minutes for Creator/Enterprise accounts, but this is **not five minutes of novel generated footage** and audio from the source clip is removed. Install both `ffmpeg` and `ffprobe` in the worker runtime. Before promising five-minute outputs commercially, load-test worker CPU/disk capacity, object-store upload limits, and provider terms.

## Checkout fulfillment setup

Stripe credit packs are one-time payments. Before enabling payments, run `packages/database/src/migrations/20260926_secure_credit_fulfillment.sql` in Supabase SQL editor. The verified Stripe webhook calls this atomic, idempotent RPC so retries cannot grant credits twice. Test with Stripe test keys and Stripe CLI before switching to live keys.

## Production checklist

The worker runtime also needs the `ffmpeg` and `ffprobe` executables available on `PATH` for rendering, probing, and metadata embedding.

Required runtime values include:

- Web: `NEXT_PUBLIC_APP_URL`, `NEXT_PUBLIC_API_URL`, `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`, `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY`
- API: `FRONTEND_URL`, `CLERK_SECRET_KEY`, `CLERK_ISSUER`, `CLERK_JWKS_URL`, `CLERK_WEBHOOK_SECRET`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `REDIS_URL`
- Worker: `HF_TOKEN`, `HUGGINGFACE_MODEL_ID`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `STORAGE_BUCKET`, `REDIS_URL`

Before production, confirm API/worker connectivity, Clerk session verification, Stripe webhook fulfillment, generated MP4 playback and downloads, privacy/consent copy, storage access controls, and actual per-plan credits/limits. Complete legal review for applicable regions and provider licenses.
